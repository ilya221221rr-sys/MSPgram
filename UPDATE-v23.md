# MSPgram v23 «Always On» — как обновиться

Что нового:
* 🔔 **Диагностика push** (Настройки → «Диагностика push»). Показывает по шагам, почему сообщения не приходят при закрытом приложении: разрешение, Service Worker, подписка устройства, Edge Function, секреты VAPID, совпадение секретов, триггер в базе и **HTTP-ответ функции на последнее сообщение** (401 / 403 / 404 / 500 с подсказкой, что чинить). Там же кнопки «Подключить» и «Тест с сервера».
* 🔕→🔔 Новое сообщение в чате теперь **снова звенит и вибрирует**, даже если старое уведомление этого чата ещё висит (раньше новое молча подменяло старое — выглядело так, будто сообщение не пришло).
* ♻️ Подписка на push **обновляется при каждом возвращении в приложение** и при появлении интернета.
* ✏️ **Админ может менять юзернеймы и имена игроков**: в Админ-панели → Пользователи → кнопка ✏️ (или карточка пользователя → «Имя и юзернейм»). Нормальное окно вместо `window.prompt` (в APK он не работает), проверка формата, понятная ошибка «юзернейм занят».

## 1. Залить файлы (2 минуты)
Распакуй `MSPgram-v23-update.zip` **поверх** папки репозитория (с заменой; `js/config.js` в архиве нет — ключи не затрутся):

```bash
git add -A
git commit -m "MSPgram v23: диагностика push, смена юзернеймов админом"
git push
```
Через сайт GitHub: Add file → Upload files → перетащи содержимое архива → Commit changes.
GitHub Pages обновится за 1–2 минуты. В приложении закрой его полностью и открой снова.

## 2. База данных (1 минута)
Supabase → SQL Editor → вставь весь `supabase/migration-12-v23.sql` → Run.
(Без неё смена юзернейма всё равно работает; миграция добавляет проверки и данные для диагностики.)

## 3. Обнови Edge Function
Supabase → Edge Functions → `send-push` → вставь новый код из `supabase/functions/send-push/index.ts` → Deploy
(«Verify JWT» должен остаться **выключенным**). Через CLI: `supabase functions deploy send-push --no-verify-jwt`.

## 4. Почему сообщения могут не приходить при закрытом приложении
Закрытое приложение получает сообщения **только** через серверный Web Push. Он работает, когда выполнено всё:

| Что нужно | Где |
|---|---|
| `migration-11-webpush.sql` | SQL Editor |
| Запись `function_url` и `webhook_secret` в `push_settings` | SQL Editor |
| Секреты `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, `PUSH_WEBHOOK_SECRET` | Edge Functions → Secrets |
| Функция `send-push` задеплоена, **Verify JWT выключен** | Edge Functions |
| Push включён на каждом устройстве | Настройки → Push-уведомления |

Ключи и готовый SQL удобно сгенерировать на странице-помощнике (рядом с архивом обновления).
После настройки открой **Настройки → Диагностика push** — все пункты должны быть ✅, затем нажми «Тест с сервера» и закрой приложение.

**Важно про APK.** Если приложение — «голый» WebView-APK, Web Push в нём не работает вообще (так устроен Android) — диагностика покажет это красным пунктом «Оболочка приложения». Решения:
* ставить сайт как PWA через Chrome («Установить приложение») — push работает;
* пересобрать APK через **PWABuilder** или **Bubblewrap** (это TWA на базе Chrome) — push работает.

Также: на Android не должно быть включено «Экономия заряда / ограничение фоновой работы» для Chrome/приложения, а на iPhone сайт должен быть добавлен «На экран Домой» (iOS 16.4+).
